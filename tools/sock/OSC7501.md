# OSC 7501 Program Status Protocol

agent-sock 支持 OSC 7501（Program Status Protocol，Mitchell Hashimoto 提出），
程序通过 pty 原生上报自身状态，orchestrator 直接读结构化状态，不再靠
`capture-pane -p` 纯文本启发式猜测。

Spec：https://www.superlogical.com/rex/docs/build/program-status（rev 0.4）。
实现严格按 spec，不发明 spec 没说的东西。

## 诚实的技术约束：tmux 吞 OSC

实测结论（`tests/test_osc7501.py::TestTmuxIntegration` 覆盖）：
tmux 消费掉自己不认识的 OSC 序列，`capture-pane -e` 里看不到程序发出的
OSC 7501。因此 pane 输出解析是 best-effort，可靠通道是 sidecar 文件。

设计（双写）：

```
worker pane                                orchestrator
┌──────────────┐                           ┌──────────────────┐
│ asock_emit_status working ...            │ agent_status(target)
│   ├─ OSC 7501 ──► pty ──► 真终端可见      │   ├─ capture_raw 解析（pty 保留时有效）
│   └─ append ──► $ASOCK_7501_FILE ────────►│   └─ sidecar 文件解析（tmux 下可靠）
└──────────────┘                           └──────────────────┘
```

- 发射端永远发 OSC 序列（真终端兼容），同时当 `$ASOCK_7501_FILE`
  设置时追加到文件（一行一个完整序列）。
- `spawn_agent(..., status=True)` 建 sidecar 文件并注入环境变量。
- `agent_status(target)` 两路合并，后读到的报告覆盖同 id 记录。

## 状态映射

agent-sock 此前没有 agent 任务状态枚举（只有 session 连接状态
active/lost/suspect，那是另一个维度）。OSC 7501 的五个状态 1:1 成为
agent 任务状态的规范表示：

| OSC 7501 state | 含义 | agent-sock 语义 |
|---|---|---|
| `idle` | 静置，等用户下一步指令 | agent 空闲 |
| `working` | 运行中，可带 progress | agent 执行任务中 |
| `done` | 做完，结果待查看 | 任务完成 |
| `blocked` | 卡住等用户，kind 说明要什么 | 等待用户输入（permission/question/auth） |
| `error` | 失败停止 | 任务失败 |
| `clear` | 非状态：删除记录及子记录 | 清理状态 |

## 用法

### 解析（读）

```python
from agent_sock import osc7501

store = osc7501.RecordStore()
store.ingest(raw_bytes)          # pty 字节流或 sidecar 文件内容
store.snapshot()                 # {"records": [{id,state,kind,progress,app,title,msg}]}
```

### 发射（写，Python）

```python
seq = osc7501.emit("working", app="deploy", msg="Pushing image", progress=40)
sys.stdout.write(seq); sys.stdout.flush()
```

### 发射（写，POSIX sh）

```sh
. ~/.agent-sock/osc7501.sh        # TmuxTool.install_shell_helper() 生成
asock_emit_status working msg="Deploying" app=deploy progress=40
asock_emit_status blocked kind=permission msg="Approve deploy to prod?"
asock_emit_status done msg="Deployed"
asock_emit_status error msg="rsync failed"
```

### TmuxTool 集成

```python
tool = TmuxTool()
tool.install_shell_helper()                    # 写 ~/.agent-sock/osc7501.sh
tool.spawn_agent("agent-7", "./worker.sh", status=True)
...
st = tool.agent_status("asock-agent-7:0")       # 结构化状态或 None
# st == {"records": [{"id": None, "state": "working", "kind": None,
#                     "progress": 40, "app": "deploy",
#                     "title": None, "msg": "Pushing image"}]}
```

新增方法：`capture_raw(target)`（bytes，保留转义序列）、
`status_file(agent_id)`、`install_shell_helper()`、
`agent_status(target)`。`spawn_agent` 加 `status=False` 可选参数，
默认行为不变。

## 解析器行为（按 spec）

- 未知 key 忽略；重复 key 取最后一个；非法 id / 非法 state 整条丢弃
  （非法 id 不回退到 root）。
- malformed pair（无 `=`、空 key、值字符集外字节）跳过该 pair，
  其余继续处理。
- `msg`/`title` 为标准 base64（padding 可选）；解码失败、超长、
  含控制字符则整条丢弃。限制：msg 2732/2048 字节，title 256/192 字节。
- `kind` 仅 `blocked` 有效（permission/question/auth），其他状态下忽略；
  非法值视为缺席。`progress` 仅 working/blocked 有效，0–100 整数，
  否则视为缺席（indeterminate）。
- `app` 非法字符集视为缺席；无 app 的记录显示时继承最近祖先的 app。
- 每个 pane 最多 256 条记录，超限淘汰最久未更新的。
- `state=clear` 删除指定记录及子记录；无 id 则清空全部。

## 协议层决策：不加新原语

XML wire 协议（11 原语）不需要为 OSC 7501 加东西：

1. OSC 7501 记录归属单个 terminal（pane），是 pane 拥有者本地观察到
   的状态。`agent_status` 的调用方和 pane 的启动方是同一进程，
   没有跨进程边界，不需要 wire 传输。
2. 加原语会制造"谁是权威"的二义性（本地观察 vs 线上传输），
   而收益为零——今天没有消费者需要跨进程读 agent 状态。
3. 将来若有需要，`agent.card` 可携带状态快照；到时再加，不做
   投机性协议设计。
